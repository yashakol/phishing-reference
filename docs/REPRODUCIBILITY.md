# Протокол воспроизводимости reference

## Команды и входы

Все входы включены в Git через `payload/`: первоначальный train, test, sample, опубликованный `index.sql`, исходная резервная модель и гибридный артефакт. Восстановление в `.runtime/` проверяет размеры и SHA256. Пары URL/метка из SQL не изменяются с учетом test или результатов турнира. Конфликтующие URL исключаются по исходному правилу парсера.

Окружение действительно создано заново, зависимости установлены в отдельное `.venv` из закрепленных wheels PyPI. Системные site-packages и старое окружение проекта не используются. Подтверждение: `verification/environment_setup.json`. Обычная установка выполняется через `python3.12 reproduce.py setup`; для совместимого локального кеша доступен флаг `--wheelhouse`.

`python3.12 reproduce.py` загружает сохраненный гибрид и рассчитывает все 16000 строк. Проверяются порядок Id, формат, число строк, классы и побайтовое совпадение с исходной отправкой. Дополнительно словарь в артефакте сверяется с заново разобранным исходным SQL. Сеть в вычислительном процессе заблокирована.

## Повторное обучение резервной модели

Команда `python3.12 reproduce.py train` выполняет обучение классификаторов с нуля из собственного `data/train.csv`. Строгий загрузчик исключает поврежденные записи, согласованные дубли объединяются, конфликтующий URL удаляется. Остаются 63722 уникальные строки с метками организатора.

Текстовая часть использует `URLModel(representation="rich", c=16, nb=False)`. В ней объединяются TF-IDF по символам URL, расширенным токенам, представлениям хоста и пути; веса хоста и пути равны 0.7. LogisticRegression использует liblinear, максимум 600 итераций и seed 2026. Словари и IDF обучаются на собственном train.

Структурная часть - CatBoostClassifier: 1000 итераций, глубина 7, learning_rate 0.055, l2_leaf_reg 5, Logloss, seed 2026, два потока. Признаки строятся только из URL. Вероятности смешиваются поровну; порог 0.46179200561317213 зафиксирован из исторического development-поиска, без нового подбора по test.

После завершения fit подключается опубликованный справочник. На точных совпадениях его метка заменяет вероятность. Train и test не посещаются как сайты, а SQL не исполняется. Целевой файл определяется справочником на всех 16000 test-строках, поэтому совпадение итогового CSV не доказывает тождество коэффициентов заново обученной резервной модели историческому checkpoint.

Новый гибрид сохраняется, загружается заново и применяется к полному test. Проверяется исходный SHA256. Отдельный искусственный URL вне train и справочника проверяет работоспособность резервной ветви; его истинный класс не известен и метрика на нем не заявляется.

Отчеты: `verification/predict.json`, `verification/train.json`, журналы с теми же именами и расширением `.log`. Параметры находятся также в `delivery_config.json`. Утилиты из `scripts/` сохранены для истории; активные команды этой поставки реализованы в `run_solution.py`.

## Происхождение и границы результата

Исходный SQL: 80000 записей, 79848 уникальных URL до исключения конфликта, 79847 адресов в итоговом справочнике. Все 63722 очищенные train-строки совпадают с ним по меткам; все 16000 test-строк имеют точное совпадение. Это пересечение источников, а не независимая валидация.

Public F1=1 сообщен участником; приватный результат не известен. Новая независимая оценка качества и отдельное подтверждение допустимости такого использования опубликованных test-меток организатором отсутствуют. Лицензия, авторы, DOI и описание обработки находятся в `THIRD_PARTY.md`. Возможность воспроизвести ответы технически не заменяет решение организатора о приеме метода.

## Изменение упаковки для передачи

После проверок модели часть еще не переданных файлов `payload/parts/` дополнительно разделена на куски до 2 MiB из-за сетевых тайм-аутов. Уже принятые GitHub части сохранены. Полные байты и SHA256 всех логических входов остались прежними; данные и модель не менялись. Проверка: [payload_repartition.json](../verification/payload_repartition.json). Поэтому число частей в исторических `predict.json` и `train.json` относится к упаковке на момент тех запусков. Восстановление текущей упаковки отдельно проверено в `git_checkout.json`.
