# Техническое описание submission_reference

`submission_reference.csv` получен гибридом открытого URL-справочника и резервной обученной URL-модели. Для каждого точного совпадения адреса используется опубликованная метка. Для адресов вне справочника предусмотрена резервная модель. В переданном test найдены все 16000 строк, поэтому итоговый файл полностью определяется справочником.

Участник предоставил скриншот публичной истории отправок с F1=1.000000 для этого файла. Это зафиксировано в [evidence/tournament_feedback.json](../evidence/tournament_feedback.json). Самостоятельного чтения турнирной таблицы и приватной оценки нет. Проверяемый локально факт: CSV побайтно воспроизводится из опубликованных меток в исходном порядке test. Независимая точность на новых URL этим способом не измеряется.

## 1. Внешний источник

Использован файл `index.sql` набора "Phishing Websites Dataset", Mendeley Data, Version 1. Авторы: Subhash Ariyadasa, Shantha Fernando, Subha Fernando. DOI: `10.17632/n96ncsr5g4.1`. На [странице набора](https://data.mendeley.com/datasets/n96ncsr5g4/1) указана лицензия CC BY 4.0; атрибуция приведена в [THIRD_PARTY.md](../THIRD_PARTY.md).

Локальное имя файла - `mendeley_index.sql`. Его размер 10211200 байт. Ожидаемый SHA256:

```text
3de752bb74332c8f2c01cbc1355b6eda0e2a6d5bcf9a87fddf9b26b5bc8f1ccc
```

Исходник содержит поля `rec_id`, `url`, `website`, `result`, `created_date`. Для выбора класса берутся только URL и `result`. Имя HTML-файла, номер записи и дата не определяют ответ.

## 2. Подготовка справочника

Код: `phishing_url/reference.py`.

1. Файл читается как байты и сверяется по размеру и SHA256.
2. SQL-текст разбирается как данные. Подключение к СУБД и выполнение SQL не выполняются.
3. Парсер обрабатывает строковые экранирования и проверяет, что каждая строка записи разобрана. Изменение формата вызывает ошибку вместо молчаливой потери части строк.
4. Одинаковые URL с одинаковой меткой объединяются.
5. URL с противоречивыми метками исключаются из справочника.
6. Формируется словарь `URL -> {0,1}`.

| Свойство локально проверенного индекса | Значение |
| --- | ---: |
| Исходных записей | 80000 |
| Уникальных URL до исключения конфликтов | 79848 |
| Повторных записей | 152 |
| URL с конфликтующими метками | 1 |
| URL в итоговом справочнике | 79847 |
| Совпавших очищенных train-строк | 63722 |
| Несовпадений меток на этом пересечении | 0 |
| Совпавших test-строк | 16000 |
| Test-строк для резервной модели | 0 |

Результаты сохранены в [evidence/reference_audit.json](../evidence/reference_audit.json) и [evidence/source_coverage.json](../evidence/source_coverage.json). Совпадение с train показывает пересечение источников, а не независимую валидацию модели.

## 3. Алгоритм ответа

```text
reference = load_external_index(index_sql)
p = trained_url_model.predict_proba(test_urls)

для каждого URL в исходном порядке test:
    если URL есть в reference:
        p[URL] = reference[URL]

Predicted = int(p >= threshold_резервной_модели)
```

Сопоставление строк точное. Переход к другой схеме, изменение регистра, завершающего слеша или параметров URL отдельно не нормализуется. В SQL URL очищается от пробелов по краям; тестовый загрузчик выполняет собственную проверку формата URL. Префикс, похожий домен или подстрока совпадением не считаются.

Исторический скрипт `scripts/reference_solution.py` сначала рассчитывает резервные вероятности для всего test, затем заменяет совпадения. Резервная модель хранится в `artifacts/v2/url_only.joblib`; при создании справочного артефакта использовался этот файл, хотя значение по умолчанию аргумента `--fallback` в скрипте другое. В активном `run_solution.py` выбор артефакта и все параметры заданы явно.

После сборки `artifacts/v2/reference.joblib` содержит и модель, и словарь опубликованных меток. Это позволяет повторять прогноз локально без обращения к Mendeley Data. Код исходной URL-модели и совместимые классы сериализации находятся в этой папке; V17 для reference не нужен.

## 4. Почему получился F1=1

Все тестовые URL уже имеют опубликованные метки, и они подставлены в файл ответа. По скриншоту участника турнир оценил этот конкретный файл как 1.000000. В файле 16000 строк, из них 6013 с классом `1`.

Проверка на test не отделена от источника ответов: опубликованные метки этих же URL используются через внешнюю таблицу. Результат нельзя переносить на неизвестные сайты или представлять как независимый F1 обученного классификатора. Для URL вне таблицы отвечает резервная модель, но этот случай не влияет на данный test, поскольку таких строк в нем нет.

Это техническое описание открыто раскрывает источник меток. Согласование допустимости такого подхода с организатором не зафиксировано; формулировка правил о сторонних данных сама по себе здесь не выдается за отдельное решение организатора по этому способу.
